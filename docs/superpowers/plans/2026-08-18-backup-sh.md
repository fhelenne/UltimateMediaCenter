# backup.sh Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A standalone `backup.sh`, run via a user-added crontab entry, that
archives every config volume (per-*arr, Jellyfin, Calibre-web, the app's own
DB) and pushes them via `rclone` to a user-configured remote, with automatic
pruning of backups older than a retention window.

**Architecture:** Single bash script following `install.sh`'s established
conventions (`set -euo pipefail`, `log()` with timestamps, a sourceable
`main()` guard for testability). Each config volume is archived via a
throwaway `alpine` container (same pattern as `install.sh`'s
`seed_arr_configs`), then the whole batch is pushed with one `rclone copy`
call and old dated folders on the remote are pruned.

**Tech Stack:** bash, Docker, `rclone/rclone` Docker image — no host `rclone`
binary required (avoids a host-install prerequisite this plan initially
missed; matches the project's existing pattern of using throwaway Docker
containers for tools rather than host installs). The one-time `rclone
config` step also runs via `docker run -it rclone/rclone config`, with its
config directory bind-mounted to a host path (`$RCLONE_CONFIG_DIR`) so it
persists across runs.

**Spec:** `docs/superpowers/specs/2026-08-18-backup-sh-design.md`

## Global Constraints

- `backup.sh` is standalone — do not modify `install.sh` (spec: keeps a
  fully-reviewed script closed; cron setup requires a manually-configured
  rclone remote anyway, so install-time automation wouldn't help)
- No restore script — manual procedure, documented only (spec: high-stakes,
  benefits from a human reading each step)
- Media volumes are explicitly out of scope (re-downloadable via *arr)
- Cron runs scripts with a minimal environment (sparse `PATH`, no
  interactive-shell customizations) — unlike every other script in this
  project so far, `backup.sh`'s primary invocation is non-interactive cron,
  not a human typing a command; verification must account for this

### Task 1: `backup.sh` — prereqs, volume archiving, remote push

**Files:**
- Create: `backup.sh`

**Interfaces:**
- Produces: `log <msg>`, `check_prereqs`, `archive_volumes <work_dir>`,
  `push_backup <work_dir>`, globals `$RCLONE_REMOTE`, `$RCLONE_CONFIG_DIR`,
  `$TARGET_DIR`, `$LOG_FILE`, `$VOLUMES` (array), `main()` (calls
  `check_prereqs`, `archive_volumes`, `push_backup` in a temp dir with
  cleanup trap)

- [ ] **Step 1: Write `backup.sh`**

```bash
#!/usr/bin/env bash
set -euo pipefail

RCLONE_REMOTE="${RCLONE_REMOTE:-}"
RCLONE_CONFIG_DIR="${RCLONE_CONFIG_DIR:-$HOME/.config/rclone}"
TARGET_DIR="${TARGET_DIR:-$HOME/ultimatemediacenter}"
LOG_FILE="${TARGET_DIR}/backup.log"
RCLONE_EXTRA_MOUNTS=()

VOLUMES=(sonarr-config radarr-config lidarr-config readarr-config jellyfin-config calibre-web-config app-data)

log() {
  echo "$(date '+%Y-%m-%d %H:%M:%S') $*"
}

rclone() {
  docker run --rm -v "${RCLONE_CONFIG_DIR}:/config/rclone" "${RCLONE_EXTRA_MOUNTS[@]}" \
    rclone/rclone "$@"
}

check_prereqs() {
  if [ -z "$RCLONE_REMOTE" ]; then
    log "ERREUR : RCLONE_REMOTE non défini. Configurer un remote avec 'docker run --rm -it -v \$HOME/.config/rclone:/config/rclone rclone/rclone config' puis exporter RCLONE_REMOTE=nom:chemin."
    exit 1
  fi
  if ! command -v docker >/dev/null 2>&1; then
    log "ERREUR : commande 'docker' introuvable dans PATH."
    exit 1
  fi
}

archive_volumes() {
  local work_dir="$1"
  local vol full_vol
  for vol in "${VOLUMES[@]}"; do
    full_vol="ultimatemediacenter_${vol}"
    log "Archivage du volume ${full_vol}..."
    docker run --rm -v "${full_vol}:/data:ro" -v "${work_dir}:/backup" alpine \
      tar czf "/backup/${vol}.tar.gz" -C /data .
  done
}

push_backup() {
  local work_dir="$1"
  local dest="${RCLONE_REMOTE}/$(date +%Y-%m-%d)/"
  log "Envoi vers ${dest}..."
  RCLONE_EXTRA_MOUNTS=(-v "${work_dir}:/data")
  if [[ "$RCLONE_REMOTE" == /* ]]; then
    RCLONE_EXTRA_MOUNTS+=(-v "${RCLONE_REMOTE}:${RCLONE_REMOTE}")
  fi
  rclone copy /data "$dest"
  RCLONE_EXTRA_MOUNTS=()
}

main() {
  mkdir -p "$TARGET_DIR"
  exec >> "$LOG_FILE" 2>&1
  log "=== Sauvegarde démarrée ==="
  check_prereqs
  local work_dir
  work_dir="$(mktemp -d)"
  trap 'rm -rf "$work_dir"' EXIT
  archive_volumes "$work_dir"
  push_backup "$work_dir"
  log "=== Sauvegarde terminée ==="
}

if [[ "${BASH_SOURCE[0]}" == "${0}" ]]; then
  main "$@"
fi
```

Notes:
- The `rclone()` shell function shadows a possible host `rclone` binary
  on purpose — every call in this script goes through the Dockerized
  version. `RCLONE_EXTRA_MOUNTS` is set by the caller just before invoking
  `rclone` when an extra bind mount is needed, and reset to `()`
  immediately after, so it never leaks into an unrelated later call in the
  same script run.
- `push_backup`'s `[[ "$RCLONE_REMOTE" == /* ]]` check and matching bind
  mount isn't test-only scaffolding — the spec explicitly lists "autre
  disque" (a second local disk) as a valid backup target alongside cloud
  remotes, and a local-path `RCLONE_REMOTE` genuinely needs its host path
  bind-mounted into the container for the Dockerized `rclone` to reach it;
  a cloud remote (`b2:bucket`, `s3:bucket`, etc.) doesn't match the `/*`
  glob and skips this mount entirely, exactly as it should.

- [ ] **Step 1: Add `RETENTION_DAYS` and `prune_old_backups`**

Add the global near the top, with the other globals:

```bash
RETENTION_DAYS="${RETENTION_DAYS:-14}"
```

Insert this function above `main()`:

```bash
prune_old_backups() {
  local cutoff entry
  cutoff="$(date -d "-${RETENTION_DAYS} days" +%Y-%m-%d)"
  if [[ "$RCLONE_REMOTE" == /* ]]; then
    RCLONE_EXTRA_MOUNTS=(-v "${RCLONE_REMOTE}:${RCLONE_REMOTE}")
  fi
  rclone lsf "$RCLONE_REMOTE" --dirs-only 2>/dev/null | while read -r entry; do
    entry="${entry%/}"
    if [[ "$entry" < "$cutoff" ]]; then
      log "Suppression de la sauvegarde expirée : ${entry}"
      rclone purge "${RCLONE_REMOTE}/${entry}"
    fi
  done
  RCLONE_EXTRA_MOUNTS=()
}
```

Same local-path bind-mount reasoning as `push_backup` in Task 1 — a
local-disk `RCLONE_REMOTE` needs its host path visible inside the
container; a cloud remote skips it via the same `/*` glob check.

- [ ] **Step 2: Wire into `main()`**

Replace `main()`'s body:

```bash
main() {

`/usr/bin:/bin`), unlike an interactive shell — a real risk class this

### Rétention

Les sauvegardes de plus de 14 jours sont supprimées automatiquement du
remote après chaque envoi réussi (variable `RETENTION_DAYS`, ajustable).

### Restauration (procédure manuelle)

Pas de script de restauration — enjeu trop élevé pour un script qui devine
en pleine panne. Pour restaurer un service (exemple avec `sonarr`) :

1. Télécharger l'archive datée souhaitée depuis le remote :
   `docker run --rm -v ~/.config/rclone:/config/rclone -v "$(pwd):/data" rclone/rclone copy nom:chemin/AAAA-MM-JJ/sonarr-config.tar.gz /data`
2. Arrêter le service : `docker compose stop sonarr`
3. Vider le volume existant :
   `docker run --rm -v ultimatemediacenter_sonarr-config:/data alpine sh -c "rm -rf /data/*"`
4. Extraire l'archive dans le volume :
   `docker run --rm -v ultimatemediacenter_sonarr-config:/data -v "$(pwd):/backup" alpine tar xzf /backup/sonarr-config.tar.gz -C /data`
5. Redémarrer : `docker compose up -d sonarr`

Adapter le nom de volume/service pour les autres composants
(`radarr`, `lidarr`, `readarr`, `jellyfin`, `calibre-web`, `app`).
```
